# Silicon Lab · GPU 芯片设计游戏

一款中文浏览器游戏：在芯片网格中摆放计算、缓存和内存模块，测试设计，再把芯片投入量产、定价销售，用利润继续研发。

## 本地运行

需要 Node.js 20 或更新版本。项目没有第三方运行依赖，无需 `npm install`。

```sh
git clone https://github.com/ywsy2437/silicon-lab-gpu-architect.git
cd silicon-lab-gpu-architect
npm start
```

在浏览器打开 <http://127.0.0.1:4186>。存档保存在当前浏览器的 localStorage 中；清理网站数据会移除本地存档。

## 玩法

- **设计芯片**：在 16 × 12 网格中摆放 SM、Tensor、RT、L2 缓存、内存控制器和指令处理器。支持拖动、旋转、删除、撤销和重做，以及频率与制程选择。
- **优化互联**：位置决定通信路径。查看路由、拥塞热图、平均跳数和通信延迟，对比两种布局的有效吞吐与功耗。
- **测试与交付**：运行均衡、光追和 AI 工作负载，完成合同并解锁研究。
- **量产与销售**：发布已测试的芯片，选择批量和封装，承担生产成本、良率损失、销售费用与库存费用，按周结算出货和销售。
- **利润再投资**：按目标市场调整价格，升级工厂降低成本，把现金投入研发；旧型号可在研发下一代时继续销售。

快捷键：`1–6` 选择模块，`R` 旋转，`E` 切换擦除，`Delete` 删除选中模块，`Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做。

## 互联模型

`dist/fabric.mjs` 使用确定性的合成数据包模拟：有向网格、XY 路由、逐跳传输和有限吞吐的 FIFO 链路。计算单元向缓存或内存发出请求，缓存访问内存，指令处理器分派工作。排队、路径长度和完成情况会影响有效计算吞吐，通信活动会增加功耗。

默认每条链路每周期最多服务 3 个包，预热 48 个周期，再测量 192 个周期。不同工作负载具有不同通信强度。布局距离更短也可能因共享链路而更拥塞，需要结合延迟和吞吐判断。

这是用于游戏决策的简化模型：不执行 CUDA 程序，不提供真实 GPU 的周期精度预测；制程、成本、市场需求和性能分数也是游戏参数。

## 测试

```sh
npm test
```

测试覆盖摆放规则、合同、研究与存档；生产、定价、FIFO 成本、市场容量与财务结算；互联距离、延迟、共享链路拥塞、服务容量、数据包守恒及布局对性能的影响。

## 离线单文件

```sh
node bundle.mjs
```

脚本会在项目的上一级目录生成 `GPU芯片设计游戏.html`。双击该文件即可离线游玩。直接双击 `dist/index.html` 可能被浏览器的 ES module 文件访问限制拦截，请使用本地服务器或生成的单文件。

## 代码位置

| 文件 | 用途 |
| --- | --- |
| `dist/index.html`、`dist/*.css` | 页面与样式 |
| `dist/app.js` | 界面、输入与游戏交互 |
| `dist/engine.mjs` | 设计评估、进度、合同、存档与经营状态 |
| `dist/fabric.mjs` | 数据包互联模拟 |
| `dist/fabric-ui.js` | 路由、拥塞和对比界面 |
| `dist/commerce.js` | 量产、销售和经营界面 |
| `server.mjs` | 本地静态服务器 |
| `bundle.mjs` | 生成离线单文件 |
| `*-tests.mjs`、`tests.mjs` | 自动化测试 |

`dist/` 中就是可编辑的源文件，也可部署到支持 ES modules 的静态网站服务。
